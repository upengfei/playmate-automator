# Agent 发布版本自动同步实施记录

日期：2026-09-10。基线：251d0f6e5271d60a2443cd7f24adf7e020bab195。

## 已实现

- 发布读取统一为可空 release 与同步状态；移除内置 1.8.2 和前端占位版本。
- 按请求触发读取 GitHub 正式 Agent 发布及清单，5 分钟缓存，60 秒最短刷新间隔，遵守 GitHub Retry-After，整次请求共用 20 秒截止时间。并发读复用正在进行的同步，旧有效数据在刷新期间仍可用。
- 校验标签、版本、三平台架构、资产完整性、固定版本 URL 和 SHA256；不完整发布、同版本二进制变更及回退不替换当前记录。
- 使用 SQLite 事务原子切换当前发布，保留最近成功时间；已有数据库自动增加 synced_at 列。失败时保留上次有效记录，慢请求失败后重新读取其他工作进程已经保存的新版。
- CI 登记与 GitHub 同步共用清单 schema、验证和持久化规则；CI 令牌校验保留，登记内容必须与实际上传的清单及资产一致。
- 版本接口无发布时返回 503 / release_unavailable；有发布时保持原成功合同，并返回同步状态，无匹配架构时 artifact 为 null。
- 下载页显示发布状态、最近成功时间、可重试时间和手动刷新反馈；按实际平台匹配图标，不依赖资产排序。
- 升级入口处理无可用发布；推送失败返回真实反馈。管理员设置的任务最低版本准入规则保持独立，网络故障不解除该规则；不会修改设备的 Agent 运行版本。
