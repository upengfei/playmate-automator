# 录制区合并本地保存 + 录制工具里的断言能生成关键字

## 1. 本地保存回到录制区

现在「本地用例仓库」是左侧一个单独的导航页，录完还要切页面才能保存，确实割裂。改成：

- 删掉左侧「本地用例仓库」导航项和它的独立页面。
- 把本地用例的按钮和列表搬回工作台的录制区下方：保存到本地、载入编排区、重命名、删除，以及本机用例列表（紧凑列表，超出可滚动）。
- 录制停止后仍然自动存一份到本机，列表就在旁边即时刷新，不用跳转。
- 工作台其它部分（平台用例、步骤编排、右侧执行日志）保持不变；本地仓库的存取逻辑、文件位置都不变。

## 2. 录制工具条里的「元素可见 / 文本可见」没生成步骤

已核对：客户端解析器本身是支持这些断言的——把真实录制脚本里的
`await expect(page.getByRole('heading', ...)).toBeVisible();`
喂给解析器，能正确解析成「断言可见」「断言文本包含」等步骤。

问题出在录制的启动参数：录制用的是 Playwright 的「库模式」输出（`--target=javascript`），这种模式下录制工具条上的断言按钮不会写进脚本文件，所以点了也等于没录。断言只在「测试模式」输出里才会写出来。

改法：

- 录制改用测试模式输出（`--target=playwright-test`），这样可见 / 不可见、文本、输入值、勾选、数量、快照等断言都会真实落进脚本。
- 解析器已经会跳过测试文件的外壳（`import`、`test(...)` 包裹），无需改解析规则；再补一组按真实测试模式脚本的解析用例。
- 用真实浏览器录制一次，点工具条上的「元素可见」「文本可见」，确认编排区出现对应的断言步骤，并能本地调试执行。

## 技术细节

- `agent-app/recorder.cjs`：codegen 参数 `--target=javascript` 改为 `--target=playwright-test`；若解析时发现残留的测试外壳语句，继续按现有规则忽略而不是标成「待转换步骤」。
- `agent-app/workbench.html`：移除 `data-view="local"` 导航与 `#panel-local`，把 `#section-local` 面板放回录制卡片下方；`viewCopy` 去掉 `local`；本地保存成功后不再切换视图。
- `tests/recorder.test.cjs`：新增「测试模式脚本 + 工具条断言」的解析用例；跑全量 `tests/*.test.cjs` 与构建。
- 生效需要重新打包客户端（本轮先改代码与验证，打包按你确认再做）。
