# 录制断言完整落地 + 客户端本地用例仓库

## 问题现状（已核对代码）

1. 录制解析是「逐行匹配」的，且断言白名单很窄：`agent-app/recorder.cjs:99` 只认 `toContainText / toBeVisible / toBeChecked / toBeEnabled / toHaveValue`。
   - 图中工具条里的「快照断言（`toMatchAriaSnapshot`）」在 Playwright 里生成的是跨多行的模板字符串，逐行匹配必然失败，只会变成一堆「待转换步骤」。
   - 「元素不可见」这类 `expect(...).not.toBeVisible()`、以及 `toHaveText / toHaveCount / toHaveAttribute / toBeHidden / toBeDisabled` 都不在白名单里，直接被丢成「待转换步骤」，所以在编排里看不到。
2. 客户端目前没有本地用例仓库：录制结果只存在当前页面内存里，只能立刻上传平台或手动导出文件（`agent-app/main.cjs` 只有平台拉取/上传，没有本地保存）。

## 要做的事

### 一、录制的断言全部变成步骤

- 解析前先把脚本里的多行语句合并成完整语句（识别反引号模板与括号配平），再逐条解析，快照断言不再被拆碎。
- 扩展断言映射，覆盖录制工具条能产生的全部断言：
  - 可见 / 不可见、文本包含 / 文本完全相等、输入值、勾选状态、可用 / 禁用、元素数量、属性值、快照断言。
- 新增对应关键字（客户端 `agent-app/keywords.cjs` 与平台 `src/lib/keywords.ts` 同步，保证两端脚本一致）：
  断言不可见、断言文本相等、断言禁用、断言元素数量、断言属性、快照断言（多行文本）。
- 仍然无法识别的语句继续保留为「待转换步骤」，不静默丢弃。
- 断言步骤同样遵守 Frame 上下文（进入 / 返回 iframe 的步骤照旧生成）。

### 二、客户端本地用例仓库

- 在客户端数据目录新增 `local-cases.json`（与配置同目录），保存：名称、起始地址、步骤、脚本、来源（录制 / AI / 平台）、更新时间。
- 主进程新增本地仓库接口：列表、读取、保存 / 覆盖、重命名、删除；预加载同步暴露给工作台页面。
- 工作台「平台用例」旁增加「本地用例仓库」列表：
  - 录制结束后自动存一份草稿到本地仓库，不联网也不丢；
  - 点击载入到编排区继续修改、本地调试；
  - 「保存到本地」「上传到平台」「导出文件」「删除」并存，上传成功后标记来源与时间。
- 离线模式下本地仓库完全可用；平台相关按钮保持现有的离线禁用逻辑。

## 技术要点

- 改动文件：`agent-app/recorder.cjs`（多行合并 + 断言映射）、`agent-app/keywords.cjs`、`src/lib/keywords.ts`（新增断言关键字与脚本模板）、`agent-app/local-cases.cjs`（新增仓库模块）、`agent-app/main.cjs`、`agent-app/preload.cjs`、`agent-app/workbench.html`。
- 平台侧只加关键字定义与脚本生成，接口、数据库结构不变；旧用例不受影响。
- 测试：在 `tests/recorder.test.cjs` 增加各类断言与快照断言的解析用例，新增本地仓库的增删改查测试，并跑一遍现有全量测试与构建。
- 生效需要重新打包客户端（本轮先改代码与验证，打包按你确认再做）。
