# 修复「执行节点管理 / Agent 仪表盘」打不开

这两页在你的浏览器里显示「This page didn't load」，但在沙箱里能正常打开，说明不是页面本身写错，而是**数据加载失败后页面直接崩掉**。

## 已确认的情况

- 两个页面服务端返回正常（HTTP 200），沙箱内用真实登录会话打开也能渲染出设备卡片和统计。
- 页面数据来自共享的平台数据缓存层（`src/lib/store.ts`）。加载成功时用返回结果**整体替换**内部状态；一旦返回结果缺少某个字段（例如版本发布信息 `release`、系统设置 `settings`），页面读取 `release.version`、`settings.minAgentVersion` 时就会抛错，落到全局错误页「This page didn't load」。
- 加载失败时只在控制台打印错误，页面上没有任何提示，所以看起来就是「打不开」。

具体是哪个字段缺失，目前还没在你的环境里抓到，所以第一步是把真实错误显示出来。

## 修复方案

1. **数据合并而不是整体替换**：拉取到的数据与默认结构合并，任何缺失字段都退回安全默认值，页面不会再因为少一个字段而崩溃。
2. **两页各自加上错误提示区**：加载失败时，页面照常显示框架和空状态，并在顶部显示一条「数据加载失败，点击重试」的提示，附上真实错误信息，而不是整页白掉。
3. **节点统计接口容错**：Agent 仪表盘的统计请求失败时保留上一次数据并标记「统计暂不可用」，不影响设备列表显示。
4. **修复后验证**：在浏览器里实际打开这两页，确认正常渲染，并在故意让数据加载失败的情况下确认显示的是提示条而不是错误页。

## 技术说明

- `src/lib/store.ts`：`refresh()` 改为 `state = { ...defaultState, ...snap, loaded: true }` 形式的深度安全合并，并记录 `loadError` 到 state，供页面读取。
- `src/routes/agents.tsx`、`src/routes/agent-dashboard.tsx`：读取 `loadError` 渲染提示条 + 重试按钮；对 `release`、`settings` 的访问改为可选取值。
- 两个路由补上各自的 `errorComponent`，显示真实错误信息，避免再退到根错误页。
- 不改任何数据库结构、接口协议或业务逻辑。
