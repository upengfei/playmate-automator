# 客户端本地编排调试 + 修复改完用例仍失败 + 无头开关

## 1. 录制后可在客户端直接编排、编辑、调试

客户端工作台的「录制」和「用例」面板改为同一个可编辑的步骤编排区：

- 录制结束解析出的步骤直接进入编排区，每一步可改：关键字（下拉）、定位（选填，可写 `${变量}`）、取值（按键等有候选时下拉 + 自定义）。
- 支持新增步骤、删除、上移/下移，条件与循环积木也在下拉里，按层级缩进显示。
- 右侧实时显示生成的 Playwright 脚本，可复制。
- 编排区顶部按钮：本地调试运行（真实浏览器）、重新运行、上传到平台。
- 从平台拉取的用例点开后同样进入这个编排区，可本地改完先调试，再上传为新版本。

关键字定义在客户端内置一份与平台一致的中文清单（含选填定位、按键候选、条件/循环），保证生成脚本和平台一致。

## 2. 修复「平台改完用例，第二次执行一闪而过还是失败」

已确认原因：任务里的用例版本号是创建任务时锁定的。平台上修改用例后版本会加 1，而重新下发时不刷新这个版本号，下发接口就认为「任务锁的是旧版本」，于是取历史快照下发——客户端第二次执行的仍然是旧的、失败的那份步骤，所以很快又失败。

修复：

- 重新下发时把每条执行记录的用例版本、名称、步骤数刷新为当前最新版本（只有用户在版本历史里明确指定旧版本时才保留锁定）。
- 下发日志明确写出本次执行的版本号，任务详情可直接看到「本次执行 v3」。
- 客户端每次执行前按用例 ID 重新拉一次最新内容，避免本地列表里是旧步骤。
- 失败时不再「一闪而过」就没了：失败步骤自动截图，日志写出失败步骤序号、定位器、真实报错，并可开启「失败后保留浏览器窗口」便于现场排查。

## 3. 执行是否无头可配置

- 客户端设置里新增「无头执行」开关（本地持久化）：平台下发的任务默认无头执行；本地调试默认有头，方便观察。
- 编排区调试按钮旁提供本次运行的有头/无头选择，覆盖默认值。
- 托盘菜单同步显示当前模式。

## 技术要点

- `src/lib/platform.functions.ts` 的 `sendTask`：更新 `case_runs` 时同步 `case_version` / `case_name` / `step_total` 为 `repo.getCase()` 的当前值，新增可选 `pinVersion` 以保留历史版本下发能力。
- `agent-app/keywords.cjs`（新增）：关键字元数据 + 脚本生成，供 `workbench.html` 与 `runner.cjs` 共用。
- `agent-app/workbench.html`：新增步骤编排组件、脚本预览、调试/上传按钮；`preload.cjs` 增加 `getKeywords`、`getRunOptions`、`setRunOptions`、`fetchCase`。
- `agent-app/main.cjs`：`executeCase` 注入 `headed`（来自配置或单次覆盖）与执行前用例刷新；`runner.cjs` 增加失败截图与可选保留浏览器。
- 验证：类型检查、CJS 语法检查、构建；并跑一遍「用例先失败 → 平台改好 → 重新下发」确认第二次执行用的是新版本且通过。
